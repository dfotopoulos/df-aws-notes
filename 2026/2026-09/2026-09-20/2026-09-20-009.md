## Summary

You have noticed a fundamental architectural distinction in cloud computing:
**AWS Cloud Users (IAM)** and **Windows Operating System Users** live in two
completely separate worlds.

I have documented this in detail in
[ `docs/iam-vs-os-users.md`](file:///C:/usr/src/df/cloud/aws/df-aws/docs/iam-vs-os-users.md).
Here is how it works:

---

### The Two Separate Layers

```
=============================================================================
 LAYER 1: AWS Cloud Control Plane (Infrastructure Level)
=============================================================================
  User:  IAM User "df" (arn:aws:iam::275517639819:user/df)
  Where: AWS Cloud (AWS Console, AWS CLI)
  Role:  Turns the VM on/off, configures firewall/VPC, modifies disks
  Login: AWS Access Keys / AWS Console login

                              |
       (Powers on & boots)    |
                              v

=============================================================================
 LAYER 2: In-Guest Operating System (Windows Server Level)
=============================================================================
  User:  Windows Local User "Administrator"
  Where: Inside the VM's hard drive (C:\Windows\System32\config\SAM)
  Role:  Runs programs on Windows, manages local files & registry
  Login: Remote Desktop (mstsc) with decrypted Windows password
```

### Real-World Analogy

Think of ordering a custom laptop from Dell:

- Your **Dell website account** allows you to purchase the hardware, turn on
  warranty support, or order a replacement.
- When the laptop arrives and boots up, Windows has its own local user account
  (`Administrator`). The Windows OS on the SSD has no connection to your Dell
  website login.

Likewise, **IAM user `df`** is your cloud infrastructure manager. The
**`Administrator`** user is the built-in account inside the Windows OS that AWS
pre-installed on the virtual machine.

---

### How to Create a Windows Account Named `df` Inside the VM

If you want to log into the Windows desktop with username **`df`** and your own
custom password:

1. Connect to the VM as `Administrator` (e.g.
   `.\scripts\manage-vm.ps1 connect`).
2. Inside the Windows Remote Desktop, open **PowerShell as Administrator**.
3. Run these three commands to create user `df`:
    ```powershell
    # 1. Create user 'df' with your preferred password
    net user df "YourSecurePassword123!" /add

    # 2. Grant local administrator rights
    net localgroup Administrators df /add

    # 3. Allow user 'df' to log in via Remote Desktop
    net localgroup "Remote Desktop Users" df /add
    ```
4. Disconnect from Remote Desktop.
5. You can now log into Windows via `mstsc` as:
    - **User name**: `.\df`
    - **Password**: `YourSecurePassword123!`
