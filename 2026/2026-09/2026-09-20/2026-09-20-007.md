## Summary

### Why You Have Two Users in AWS

In AWS, there are two distinct types of user identities:

```
+---------------------------------------------------------------------------------+
| AWS Account: 275517639819 (Root User: your-email@example.com)                   |
|   - Complete, unrestricted owner access (billing, account closure, support)     |
|   - Best practice: Never use for daily tasks or CLI access                      |
|                                                                                 |
|   +-------------------------------------------------------------------------+   |
|   | IAM User: df (arn:aws:iam::275517639819:user/df)                        |   |
|   |   - Purpose: Day-to-day operations and CLI/automated tasks              |   |
|   |   - Permissions: Only what you explicitly attach (e.g. EC2)              |   |
|   |   - Access Keys: Configured in your local AWS CLI                       |   |
|   +-------------------------------------------------------------------------+   |
+---------------------------------------------------------------------------------+
```

| Feature              | Root User (Account Owner)                                 | IAM User (e.g. `df`)                                      |
| :------------------- | :-------------------------------------------------------- | :-------------------------------------------------------- |
| **How It's Created** | When you first register the AWS account with an email.    | Created by you inside the AWS account.                    |
| **Login Identifier** | Your email address + root password.                       | Account ID (`275517639819`) + Username (`df`) + password. |
| **ARN Format**       | `arn:aws:iam::275517639819:root`                          | `arn:aws:iam::275517639819:user/df`                       |
| **Permissions**      | **Unrestricted access to everything**. Cannot be limited. | **Explicitly granted**. Starts with zero permissions.     |
| **CLI Access**       | Dangerous. AWS strongly advises against root access keys. | Recommended. Keys can be revoked or rotated anytime.      |

_Explanation: This proves your CLI commands run as IAM user `df` inside AWS
Account `275517639819`._

#### 2. Understanding IAM Least Privilege (`AccessDenied` Example)

When we run:

```powershell
aws iam get-user
```

AWS returns:

```text
(AccessDenied) User: arn:aws:iam::275517639819:user/df is not authorized to perform: iam:GetUser
```

**Why this happens:**

- User `df` has permissions to control **EC2 virtual machines** (start, stop,
  describe, reboot, retrieve passwords).
- However, user `df` has **not** been granted permissions to inspect or modify
  the **IAM service**.
- This is AWS's security boundary: an IAM user cannot see other users or inspect
  policies unless specifically authorized by the Root administrator.

---

#### 3. How to Grant User `df` Permission to Inspect IAM Details

If you want user `df` to also be able to view IAM users, policies, and
credentials:

1. Log in to the [AWS Management Console](https://console.aws.amazon.com/) as
   **Root** (using your email).
2. Go to **IAM** &rarr; **Users** &rarr; click on **df**.
3. Under **Permissions**, click **Add permissions** &rarr; **Attach policies
   directly**.
4. Search for:
    - `IAMReadOnlyAccess` (allows viewing IAM details without changing
      anything), or
    - `AdministratorAccess` (full administrative rights across all AWS
      services).
5. Click **Next** &rarr; **Add permissions**.

Once attached, these commands will succeed:

```powershell
# View details for user df:
aws iam get-user --user-name df

# View which policies are attached to user df:
aws iam list-attached-user-policies --user-name df

# View active access keys for user df:
aws iam list-access-keys --user-name df
```
