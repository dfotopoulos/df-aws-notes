## Summary

Yes.
[scripts/manage-vm.ps1](file:///C:/usr/src/df/cloud/aws/df-aws/scripts/manage-vm.ps1)
has been updated with this exact workflow:

1. **Mandatory `-Name`**: Creation requires a VM name (cannot be left blank).
2. **Duplicate Check & Status Reporting**: If an active VM with that name
   already exists, the script halts smoothly and prints:
    - The error stating it cannot be created because it already exists.
    - The live status report of the existing VM (Instance ID, Current State,
      Type, Public IP, Private IP, Launch Time).
3. **Creation & Waiting for Full Availability**: If the VM does not exist, it
   launches the instance and waits not just for the hypervisor `running` state,
   but actively polls TCP port 3389 until the Windows OS finishes booting and is
   **available** for RDP connections. It then retrieves the Administrator
   password and updates the connection shortcut.

### Example Behavior When Creating a New VM

```powershell
.\scripts\manage-vm.ps1 create -Name my-new-windows-pc
```

1. Checks that no instance named `my-new-windows-pc` exists.
2. Launches Windows Server 2025 (Windows 11 codebase) with a 120 GB gp3 SSD.
3. Waits for EC2 `running` state:
    ```text
    [+] Instance entered 'running' state!
        Instance ID   : i-0xxxxxxxxxxxx
        Public IP     : x.x.x.x
        Public DNS    : ec2-x-x-x-x.eu-central-1.compute.amazonaws.com
    ```
4. Actively waits for Windows to initialize:
    ```text
    Waiting for Windows to finish booting and become available (RDP port 3389)...
    ....................
    [+] Windows VM is fully booted and AVAILABLE for RDP connections!
    ```
5. Retrieves the Administrator password, copies it to your clipboard, and
   updates
   [windows-dev-test-pc.rdp](file:///C:/usr/src/df/cloud/aws/df-aws/windows-dev-test-pc.rdp).
