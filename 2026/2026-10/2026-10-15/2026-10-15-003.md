# 2026-10-15-003

## Summary

**No, it did not make sense** — and it has now been fixed in
[scripts/manage-vm.ps1](file:///C:/usr/src/df/cloud/aws/df-aws/scripts/manage-vm.ps1).

---

### Why That Happened

Previously, when `-Name` was passed to a command like `status`, the script
searched AWS for an instance matching that name:

1. Since `windows-dev-test-pc-001` did not exist in AWS, the search query
   returned nothing.
2. Because nothing was returned, the script silently kept the fallback default
   `$InstanceId = "i-0c69f686dce985f3f"`.
3. It then displayed the status of `i-0c69f686dce985f3f`
   (`windows-dev-test-pc`), giving the misleading impression that
   `windows-dev-test-pc-001` existed.

---

### What Was Fixed

The script now strictly checks if `-Name` was specified:

- **If found**: Resolves the exact `InstanceId` and runs the requested action
  (`status`, `stop`, `start`, `connect`, `teardown`).
- **If not found**: Immediately stops and reports an error instead of silently
  falling back to the default instance.

---

### Verification

Now, querying a non-existent name returns the expected error:

```powershell
.\scripts\manage-vm.ps1 status -Name windows-dev-test-pc-001
```

**Output:**

```text
[-] Error: No EC2 instance found with Name 'windows-dev-test-pc-001'.
```

And querying the actual existing name returns its status:

```powershell
.\scripts\manage-vm.ps1 status -Name windows-dev-test-pc
```

**Output:**

```text
Fetching status for i-0c69f686dce985f3f...
```
