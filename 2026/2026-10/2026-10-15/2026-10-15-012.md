## Summary

**No, you will not face any issues at all.**

Reusing names like `windows-dev-test-pc` and `nanomegas-format-code` for disposable test VMs is standard practice and
fully supported.

---

### Why It Works Seamlessly

1. **AWS EC2 does not treat `Name` as a unique primary key:**
    - In AWS, the `Name` is just a metadata tag (`tag:Name`). The actual identifier is the unique `InstanceId` (e.g.
      `i-078...`).
    - Even while the old instance is still temporarily visible in the console with state `Terminated`, AWS allows
      creating a new instance with the exact same `Name` immediately.

2. **[scripts/manage-vm.ps1](file:///C:/usr/src/df/cloud/aws/df-aws/scripts/manage-vm.ps1) specifically ignores
   `Terminated` instances:**
    - When checking for name collisions on `create`, the script only looks for **active** instances (`pending`,
      `running`, `stopped`, `stopping`).
    - Because the previous VM is `terminated`, the script will **not** block creation.

3. **Automatic Re-binding:**
    - As soon as the new VM is created, the script:
        - Automatically updates its default `$InstanceId` to the newly launched instance.
        - Automatically points [windows-dev-test-pc.rdp](file:///C:/usr/src/df/cloud/aws/df-aws/windows-dev-test-pc.rdp)
          to the new instance's public IP and DNS.
        - Targets the new active instance when you run commands like `status -Name <NAME>`, `stop -Name <NAME>`, or
          `teardown -Name <NAME>`.

---

### The Only Thing You Will Notice

When you connect via RDP to the newly created VM for the first time, Windows Remote Desktop will display the standard
one-time certificate banner:
> *"The identity of the remote computer cannot be verified. Do you want to connect anyway?"*

This is completely expected because it is a brand-new virtual machine with a fresh SSL certificate. Simply check **"
Don't ask me again for connections to this computer"** and click **Yes**.
